## Design specificity verdict

**Design review.** The top-level tabs are authored for this product: Trending's ember rank and "+gained" figure, the Feed's kind-first rows, the Inbox's "Needs you / Everything else" split. Quality drops on the way down. Detail screens are a competent template. The management surfaces (repository settings, the Manage list, confirmations) are category-default Material in Soft colours. The discovery reader gets the designed product; the maintainer gets the default one. Repository settings (built 2026-10-12 without a design pass) is the weakest screen; the check report holds up better because it inherits the reading layout.

**Deterministic scan.** `impeccable detect --json app`: exit 0, `[]`. It reads HTML/CSS and says nothing about Compose code; no web surface, so no browser overlay. Code searches:
- Press feedback is split: 27 `.clickable` plus 15 `.selectable`/`.toggleable` sites keep the default ripple, against 29 `softPressable` sites; `SoftButton` and `SoftTonalButton` (SoftComponents.kt:535, 552) are among the ripple ones. Inferred from code, not rendered.
- Stock selection controls with no colours passed: `RadioButton` at repo/settings/RepoSettingsScreen.kt:637, 730 and settings/SettingsScreen.kt:573; `Checkbox` at settings/SettingsScreen.kt:612. `ReviewSheet.kt:84` and `NewPullRequestScreen.kt:151` draw the same controls from icons.
- Holds: 0 dividers, cards or outlined components; 2 direct Material colour-role uses (ui/Avatar.kt:32-33); all 8 `AlertDialog` and 8 `ModalBottomSheet` sites pass Soft colours; every translatable string has a French entry.

## Overall impression

The reading half is confident and distinctive; the doing half was added quickly and shows it. The biggest opportunity is one small set of Soft pieces for high-stakes moments (a confirmation sheet, a destructive button, a selection control), which would lift repository settings, Manage, merge and delete at once.

## What's working

1. The header tint tells you where you are before you read (`trending_light.png`, `issue_light.png`, `check_light.png` vs `check_without_a_report_light.png`), and holds in dark and AMOLED.
2. Inbox triage: "Needs you" first with reason pills, the rest grouped by owner and repository, read state by weight and an ember dot, 5-second Undo (`inbox_light.png`, `inbox_undo_dark.png`).
3. Honest states and copy: row-shaped skeletons, an empty state that names its cause, signed-out walls offering "Browse Trending"; large text wraps without clipping where a 2.0 golden exists.

## Priority issues

**[P1] Deleting a repository is under-protected, and its refusal is a dead end**
- What: the confirm field uses the full repository name as its placeholder (repo/settings/RepoSettingsScreen.kt:673), so it looks typed while the button is disabled; the confirm is the standard ember `SoftButton` (:674); no Cancel; an older sign-in is refused only after typing and confirming, with instructions to go to the You tab (:253, strings.xml:860). Golden: `repo_settings_delete_refused_light.png`.
- Fix: visible label above an empty field; tonal Cancel; one destructive button treatment in Soft, used here and for issue delete; check the permission when the sheet opens and offer "Sign in again" there.
- Suggested command: /impeccable harden

**[P1] Repository settings breaks four of the design system's own rules**
- What: header tint is `colors.surface` (:312) where the tint table gives a repository warm; the danger zone is a 28dp tinted panel around four rows (:423), against "nothing boxed", reusing the warm tint, barely distinct in dark (`repo_settings_danger_dark.png`); stock `RadioButton` marks selection (:637, :730); stock `AlertDialog` + `TextButton` confirms visibility, archive and unpublish (:263, :622, :656); title at 34sp where Detail Title is 30sp (:323); no row shows it is tappable; "Address" opens a browser while its neighbours open editors (:409); folders hard-coded to "/" and "/docs" (:713).
- Fix: warm header; unbox the danger zone into a titled section with the destructive treatment on Delete only; `SoftSwitch` for two-way choices and the ember-check list for branches (as `repo_ref_sheet_dark.png`); one Soft confirmation sheet replacing the eight `AlertDialog` call sites; trailing glyph on external rows.
- Suggested command: /impeccable polish

**[P1] Merge is the primary action while checks are failing**
- What: the ember Merge sits under "1 of 2 checks failed" (`issue_pull_request_light.png`); shown whenever `canMerge` (pull/PullRequestPanel.kt:128). The merge sheet states blockers (:254-258), one tap late.
- Fix: tonal Merge when checks fail or are pending, with the checks row leading; repeat the check state at the top of the merge sheet.
- Suggested command: /impeccable harden

**[P1] Sign-in asks for delete permission without saying so**
- What: `sign_in_github_access` (strings.xml:133) says access is needed "to show them, and to comment, star and run workflows there"; `delete_repo` is in the default scopes since 2026-10-12 (forge/github/.../GitHubAuthApi.kt:95) by the owner's decision; the token instructions (strings.xml:159) name it.
- Fix: name the permission and why in that sentence, or request it only from the delete sheet.
- Suggested command: /impeccable clarify

**[P2] The pull request header is a stack of boxes**
- What: branch panel, three full-width raised rows (files, commits, checks) and two buttons fill about 57% of the first screen inside the field; nine tappables before the conversation (`issue_pull_request_light.png`). No 2.0-font golden for this screen.
- Fix: one meta line plus one check-status pill, or chip tabs under the header as the repository screen does.
- Suggested command: /impeccable distill
